# BiYou 本地知识库问答系统 —— 用户使用指南

欢迎使用 **BiYou** 本地知识库问答系统！BiYou 是一款专为个人与团队设计的本地增强检索问答系统（RAG）。所有文档解析、向量化与检索过程均在本地完成，确保您的私密资料不离开本地设备。

---

## 1. 快速启动与环境准备

### 1.1 系统要求
- **操作系统**：macOS / Linux / Windows
- **Python 环境**：Python 3.12+ (推荐使用 `uv` 包管理器)
- **Node.js 环境**：Node.js 18+ (包含 `npm`)

### 1.2 本地开发一键启动
在项目根目录打开终端，运行开发启动脚本：
```bash
./scripts/dev.sh
```
启动成功后，脚本会自动启动后端与前端服务：
- 前端访问入口：`http://localhost:5173`
- 后端 API 地址：`http://localhost:8000`

### 1.3 Docker 容器化部署指南

系统提供了 **前后端分离部署** 与 **全功能综合一体化部署** 两种 Docker 方案：

#### 方案 A：前后端分离独立部署 (推荐)
运行标准 Docker Compose 文件，前端（Nginx 80 端口）与后端（FastAPI 8000 端口）分别独立运行在两个镜像容器中：
```bash
docker-compose up -d --build
```
- 前端 Web 访问地址：`http://localhost`
- 后端 API 与 Swagger 文档：`http://localhost:8000/docs`

#### 方案 B：全功能综合一体化单容器部署
如果希望仅运行一个包含了前端 Nginx + 后端 FastAPI 的综合容器：
```bash
docker-compose -f docker-compose.all-in-one.yml up -d --build
```
- 容器一键挂载数据持久化目录 `./data` 与日志目录 `./logs`。

## 2. 页面导航与核心功能指南

系统界面采用左侧常驻导航栏，主要包含 **概览**、**知识库**、**问答**、**链路追踪**、**诊断** 和 **设置** 6 个主要页面。

```text
BiYou 本地知识库
├── 概览 (Overview)         # 整体指标卡片、处理动态与历史预览
├── 知识库 (Knowledge Base)  # 创建知识库、导入 Markdown/TXT/PDF 文档
├── 问答 (Chat)             # 自然语言对话、流式回答与引用溯源
├── 链路追踪 (Analytics)     # 查看检索切片、得分与上下文卡片
├── 诊断 (Diagnostics)       # 探针检测、满意度统计与日志控制台
└── 设置 (Settings)          # 配置 LLM / Embedding 模型与连通性测试
```

---

### 2.1 概览仪表盘 (`/overview`)
进入系统默认展示概览界面：
- **顶部指标卡片**：直观展示当前系统内的**知识库空间数量**、**导入文档数**以及**历史对话总数**。点击卡片可快速跳转至对应页面。
- **最近文档列表**：展示最新导入的文件格式（MD / TXT / PDF）、所属知识库、文件体积及“可检索 / 建立索引中”的状态。
- **处理动态流水线**：实时展示当前文档在后台解析、切片、向量化和建立索引的环形进度。
- **继续上次对话**：快速唤起最近的问答探索。

---

### 2.2 知识库与文档管理 (`/knowledge-bases`)
管理和组织您的私密文档资料：
1. **新建知识库**：点击右上角「新建知识库」，输入知识库名称与描述（例如：“项目架构文档”）。不同知识库之间的数据相互独立。
2. **导入文档**：
   - 支持拖拽或点按选择文件上传。
   - 适配格式：Markdown (`.md`)、纯文本 (`.txt`)、PDF (`.pdf`)。
   - 文件上传后，系统将自动触发后台文本切片与向量化生成。
3. **查看与管理文档**：在列表中可查看每个文档生成的文本块数量、状态及更新时间，支持删除文档或重新处理。

---

### 2.3 智能问答与引用溯源 (`/chat`)
基于本地知识库进行自然语言问答交互：
1. **选择知识库范围**：在问答页面顶部下拉菜单中选择您要查询的知识库空间（或选择全库模式）。
2. **提问交互与意图识别**：系统内置智能意图识别引擎 (`QueryRouter`)。当您提出专业技术问题时，系统自动触发知识库 RAG 检索并改写查询；当您进行日常寒暄时，系统会自动分发至通用问答，省去不必要的检索延时。
3. **查看高亮引用角标**：
   - AI 回答中会精准标注引用来源标识（如 `(1)`、`(2)`）。
   - 点击引用标识可在右侧弹窗中展示**被引用的文档原始段落**、**文本块位置**以及**匹配得分**，方便查验事实出处。
4. **满意度反馈与重新生成**：
   - **点赞 / 点踩**：对满意或不准确的回答进行 👍/👎 评价，点踩可选择具体原因（如“回答不准确”、“缺失关键上下文”）。
   - **重新生成**：若对当前回答不满意，点击「重新生成」按钮即可让 AI 重新检索并生成解答。
5. **长期记忆与个性化感知**：
   - **保存记忆**：当您发送“记住：我是前端工程师”或“记录：常用技术栈是 Python 和 TS”时，系统将自动抽取该键值对保存至长期记忆。
   - **记忆调用**：在后续通用问答中，系统会自动提取并注入该记忆上下文，使 AI 回答更具个性化与身份感知力。

---

### 2.4 链路追踪与透明化 (`/analytics`)
专为排查和理解 RAG 检索细节设计的追溯面板：
- 展示历史问答在检索阶段被命中的 **Parent / Child 文本块**。
- 可直观对比 Child 文本块的向量匹配得分、召回得分以及最终送入大模型的 Parent 段落正文。

---

### 2.5 诊断与日志控制台 (`/diagnostics`)
系统运维与服务健康检查：
- **健康检查探针**：显示应用服务、数据库连接、向量索引与模型服务实时延迟。
- **满意度与重新生成统计**：图表展示累计点赞率、点踩原因分布以及重新生成频次。
- **实时日志控制台**：按 `INFO` / `WARNING` / `ERROR` 级别筛选后台审计日志，支持输入 `Trace ID` 快速定位单次请求处理路径。

---

### 2.6 系统设置 (`/settings`)
配置您的本地或远程 AI 模型：
1. **选择 AI Provider**：
   - **OpenAI Compatible (推荐)**：支持 SiliconFlow、DeepSeek 官方 API、vLLM、LM Studio 等。
   - **Ollama (本地运行)**：选择本地已运行的 Ollama 服务（默认 `http://localhost:11434/v1`）。
2. **测试连通性**：点击「测试连接」按钮，系统会发送探针请求验证 Base URL 和 API Key 是否有效。
3. **热生效与保存**：保存设置后无需重启服务，所有问答对话将立即切换为新的模型引擎。

## 3. 常见问题解答 (FAQ)

**Q1：我的文档数据会被上传到第三方服务器吗？**
A：不会。嵌入向量模型 (FastEmbed) 与向量数据库 (LanceDB) 均在您的本地设备上运行。只有当您将 AI Provider 设置为云端模型（如 SiliconFlow / DeepSeek API）时，被检索命中的相关上下文段落才会通过安全加密通道发送给指定 API。若使用本地 Ollama，则全程 100% 离线运行。

**Q2：导入超大文档时卡住怎么办？**
A：系统后台采用异步队列切片处理。上传大文件后您可以离开页面自由切换，流水线会在后台持续运行。您可在「概览」页面的「处理动态」或「诊断」页面查看日志输出。

**Q3：为什么重新生成回答后历史反馈还在？**
A：BiYou 建立了独立的快照审计日志系统，您的反馈与重新生成行为均会被安全记录，帮助后台统计回答满意度。
